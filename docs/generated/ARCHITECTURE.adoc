== Introduction

The open oscilloscope firmware family as a system of systems: the <<REF_IDX-CATALOG_SYS_CORE,shared core>>, which is the product, and one <<REF_IDX-CATALOG_TERM_BSP,board-support package>> per <<REF_IDX-CATALOG_SYS_SCOPE,scope>>. The <<REF_IDX-ENGMODEL_TERM_MODEL,model>> composes the public models (<<REF_IDX-CATALOG_OPEN_DSO_CORE,open-dso-core>> and the SDS1000CML+) and <<REF_IDX-ENGMODEL_TERM_STATE,states>> the rules every <<REF_IDX-CATALOG_SYS_SCOPE,scope>> keeps: one product family, one <<REF_IDX-CATALOG_SYS_CORE,shared core>>, the same <<REF_IDX-CATALOG_TERM_FEATURE_LEVEL,feature level>>, the same <<REF_IDX-CATALOG_TERM_WEB_API,web API>> and look, and no <<REF_IDX-CATALOG_TERM_VENDOR_MATERIAL,vendor material>> in any public repository.

=== Scope and Assumptions

- <<REF_IDX-ENGMODEL_EM_FUNCTIONAL_GROUP,Functional Groups>> and <<REF_IDX-ENGMODEL_EM_FUNCTIONAL_UNIT,Functional Units>> are the stable authored design backbone.
- <<REF_IDX-ENGMODEL_EM_RUNTIME_ELEMENT,Runtime elements>> and <<REF_IDX-ENGMODEL_EM_CODE_ELEMENT,code elements>> are inferred from available IaC, deployment, and source artifacts.
- Inferred coverage is evidence-driven and may be partial when source metadata is missing.
- <<REF_IDX-ENGMODEL_EM_REQUIREMENT,Requirements>> and reference indexes are provided for traceability, not as primary narrative flow.

== How To Read This Document

This document is intentionally split into two layers:

1. Concept layer: functional and view-specific architecture narratives for human understanding.
2. Evidence layer: generated requirement traceability and inferred reference indexes.

Read in this order:

1. Architecture Intent View: stable authored architecture intent and ownership boundaries.
2. Communication / Deployment / Security Views: viewpoint-specific operational behavior.
3. Traceability View: requirement mapping, evidence coverage, and confidence.
4. Reference Appendix: supporting reference IDs and inferred-source links.

== Contract Items

The capabilities and assumptions of use this model publishes, each with the requirements that realize it. A using system pins the version it reviewed in its requirement links; a release that changes the text or verification criteria of an item or a realizing requirement needs a new review in every user.

=== CAP-FAM-OPEN-FIRMWARE (capability)

Open firmware for digital storage oscilloscopes as one family: the same features, the same web UI and the same look on every instrument it supports, written from the family's own specifications.

Realized by:

* `REQ-FAM-001`: The open-dso family shall describe the firmware of every public scope as one product family in the family model.
* `REQ-FAM-007`: The open-dso family shall keep vendor material out of every public repository.
* `REQ-FAM-008`: While the scope repository is unreviewed, the scope repository shall stay private.
* `REQ-FAM-009`: When a scope repository becomes public, the open-dso family shall compose the scope's model in the family model.
